# Проверка сборки

Дата: 11 ноября 2026.

## Версия 1.3.0 — горизонтальное видео, анимации и громкость

- Добавлен видеорежим с учётом ориентации устройства со скрытыми системными панелями, автоматическим скрытием управления и выходом через кнопку или «Назад». Приложение разрешает системный поворот; в горизонтальной ориентации видеоплеер автоматически занимает экран, в портретной возвращает обычную компоновку. Ручной полный экран также следует ориентации устройства. В горизонтальной медиатеке сокращён заголовок, в аудиоплеере убрана крупная обложка, чтобы оставить место управлению. Media3 остаётся в сервисе; смена режима не пересоздаёт очередь.
- Громкость приложения регулируется от 0 до 200%. До 100% используется `Player.volume`, выше — `LoudnessEnhancer`, привязанный к фактической аудиосессии. При смене сессии эффект освобождается и создаётся заново; при недоступности усилителя интерфейс ограничен 100%. Значение и поддержка передаются через медиасессию, поэтому не теряются при смене ориентации.
- Compose анимирует переключение вкладок, появление/закрытие мини-плеера, открытие/сворачивание большого плеера, изменение размеров карточек и перестроение списка. Состояние фильтров вкладки сохраняется. Иконка переведена на `AdaptiveIconDrawable` с фоном, заполняющим маску.
- `testDebugUnitTest assembleDebug -PtargetAbi=arm64-v8a`: успешно, 28 тестов. Три новых теста проверяют выключение звука и ослабление, логарифмический коэффициент усиления (+3,52 дБ при 150%, +6,02 дБ при 200%), ограничение диапазона внешних команд и отсутствие передачи громкости выше 1 в ExoPlayer.
- APK versionCode 6 / versionName 1.3.0, ARM64, minSdk 26. `apksigner verify` успешно; SHA-256 сертификата совпадает с 1.2.0 (`f78787bf9c5292d7498c14f1052485fb1476487570b6a548653d73a3fee38550`).

- На эмуляторе API 28 в финальной сборке проверен системный поворот открытого видеоплеера: портрет → горизонтальный полный экран → портрет. Размеры снимков 480×960 → 960×480 → 480×960; пауза и позиция 14744 мс сохранились во всех трёх состояниях. Тестовые медиа в пользовательский APK не включены.
- На Android проверены подключение Loudness Enhancer к сессии, переход шкалы к 200% и уменьшение кнопкой до 190%; адаптивная иконка распознана системой, крайние точки внутри маски непрозрачны. Физический телефон и реальное скачивание с YouTube этой проверкой не охвачены.

## Версия 1.1.2 — чтение версии zipapp на Android

- Исправлена ошибка «Версия загрузчика не совпала»: официальный `yt-dlp` начинается с `#!/usr/bin/env python3`, а [реализация ZipFile в Android 15](https://android.googlesource.com/platform/libcore/+/android-15.0.0_r1/ojluni/src/main/java/java/util/zip/ZipFile.java) явно отвергает файл без ZIP-заголовка в нулевом смещении (`Entry at offset zero has invalid LFH signature`). Ранее исключение подавлялось в `version()` и превращалось в несовпадение версии. На Android 9 исходный `ZipFile` такой архив принимает; это объясняет различия сред.
- Чтение переведено на `ZipInputStream` с найденного начала ZIP-содержимого. Поиск ограничен 4096 байтами преамбулы. Файл не перепаковывается и не меняется; SHA-256 по-прежнему проверяется для целого официального бинарника до установки.
- `testDebugUnitTest assembleDebug -PtargetAbi=arm64-v8a`: успешно, 20 тестов. Добавлены проверки чтения zipapp со строкой запуска, проверенной установки такого файла и отклонения некорректной/слишком длинной преамбулы.
- Скомпилированный исправленный `DownloaderCore` вместе с Kotlin runtime выполнен как DEX в настоящей Android-среде эмулятора API 28 / Dalvik 2.1.0. Для официального архива подтверждены версия 2026.10.26 и успешная `installVerified` с совпадающим SHA-256 (`Install PASS`). Это проверка Java-кода установки на Android, не сетевого поиска YouTube.
- APK: versionCode 4 / versionName 1.1.2, ARM64, minSdk 26, 76 787 918 байт. Подпись совпадает с 1.1.1; bytes `assets/yt-dlp` имеют прежнюю официальную контрольную сумму.
- Проверка на физическом телефоне пользователя и успешное скачивание с YouTube не подтверждены. Доступ к YouTube из облачной среды по-прежнему ограничен прокси, как зафиксировано для 1.1.1.

## Версия 1.1.1 — устаревший загрузчик и HTTP 403

- Воспроизведена причина устаревшей версии: AAR 0.18.1 содержит yt-dlp 2025.11.12. В новую сборку включён официальный Unix zipimport yt-dlp 2026.10.26, полученный из `yt-dlp/yt-dlp`; SHA-256 совпал с digest release asset и `SHA2-256SUMS`.
- Проверено содержимое готового APK: `assets/yt-dlp` имеет ожидаемый SHA-256, `yt_dlp/version.py` содержит 2026.10.26, присутствуют EJS-скрипты. Библиотека включает QuickJS 2025-04-26; Python — 3.12.
- `testDebugUnitTest assembleDebug -PtargetAbi=arm64-v8a`: успешно, 17 тестов. Новые тесты проверяют замену установленного ядра 2025 года реальным архивом из assets, сохранение более новой версии, целостность рабочего файла при повреждённом обновлении, проверку версии и SHA-256, официальный адрес обновления, отсутствие повторного скачивания текущей версии и распознавание ошибки 403.
- С текущим скомпилированным `DownloadRequestFactory` и новым встроенным yt-dlp повторена локальная интеграционная проверка MP4 → MP3. Получен MP3 с одним аудиопотоком без видео.
- APK: versionCode 3 / versionName 1.1.1, ARM64, minSdk 26, 76 787 102 байта. Подпись проверена и совпадает с 1.1.0.
- Сетевой тест видео со скриншота (`ffAG0BZSNwQ`) остановлен на прокси среды: CONNECT к `www.youtube.com` получает HTTP 403 до обращения к YouTube. Это отдельный сетевой барьер и не подтверждает, что ошибка пользователя устранена. Проверка скачивания на физическом телефоне остаётся необходимой; успех реальной загрузки YouTube не заявляется.

Полная цепочка получения метаданных YouTube → загрузка → остановка → продолжение → просмотр → удаление на устройстве **не подтверждена**. На медленном программном эмуляторе проверка остановилась на подготовке загрузчика/получении видео. Не следует считать проверку интерфейса доказательством скачивания. Перед повседневным использованием проверьте эту цепочку на физическом телефоне и доступном видео.

GitHub Actions сконфигурирован, но удалённый запуск пока не выполнен: создание репозитория текущим GitHub-подключением возвращает 403 `Resource not accessible by integration`. Исходники подготовлены в локальном Git-репозитории; push требует доступного удалённого репозитория.
